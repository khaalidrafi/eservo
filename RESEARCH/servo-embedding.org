* The winit_minimal example (the embedding recipe, verified)

#+begin_src rust
let servo = ServoBuilder::default()
    .event_loop_waker(Box::new(waker))   // embedder_traits::EventLoopWaker
    .build();
let webview = WebViewBuilder::new(&servo, rendering_context)
    .url(url)
    .hidpi_scale_factor(..)
    .delegate(app_state)                 // servo::WebViewDelegate
    .build();
// pump:
servo.spin_event_loop();
// frame-ready arrives via WebViewDelegate::notify_new_frame_ready
webview.paint();
rendering_context.present();
// input injection:
webview.notify_input_event(InputEvent::Wheel(WheelEvent::new(..)));
#+end_src

Source: components/servo/examples/winit_minimal.rs (URL above).

* Rendering contexts — the offscreen answer (verified)

From =components/shared/paint/rendering_context.rs=
https://github.com/servo/servo/blob/main/components/shared/paint/rendering_context.rs :

- Trait =RenderingContext=: =prepare_for_rendering()=,
  =read_to_image(DeviceIntRect) -> Option<image::RgbaImage>= (reads
  pixels back!), =size()=, =resize()=, =present()=, =make_current()=,
  =gleam_gl_api()= / =glow_gl_api()=, texture + adapter plumbing.
  All four context types are re-exported at the =servo= crate root
  (components/servo/lib.rs):
  #+begin_src rust
  pub use paint_api::rendering_context::{
      OffscreenRenderingContext, RenderingContext, SoftwareRenderingContext,
      WindowRenderingContext,
  };
  #+end_src
- =WindowRenderingContext::new(display_handle, window_handle, size)= —
  needs a REAL window (raw-window-handle). Not our path.
- =OffscreenRenderingContext= — despite the name, it is an FBO that
  blits into a *parent* =WindowRenderingContext= (constructor is
  =WindowRenderingContext::offscreen_context=). Still needs a window.
  NOT a headless path.
- =SoftwareRenderingContext::new(size: PhysicalSize<u32>)= — creates a
  surfman *software adapter* (comment in-tree references OSMesa
  headless quirks, issue #18606), no window required;
  =read_to_image= gives an =RgbaImage=. In-tree unit test
  =test_read_pixels= exercises this path. → *This is the eservo v0
  offscreen surface.*
- servoshell's own headless mode uses exactly this:
  =ports/servoshell/desktop/headless_window.rs= holds a
  =Rc<SoftwareRenderingContext>= created via
  =SoftwareRenderingContext::new(physical_size)=.
  https://github.com/servo/servo/blob/main/ports/servoshell/desktop/headless_window.rs

* WebView API surface (verified, components/servo/webview.rs)

https://github.com/servo/servo/blob/main/components/servo/webview.rs
Relevant to eservo:

- Navigation: =load(Url)=, =reload=, =go_back/go_forward=,
  =clear_session_history=, =url()=, =page_title()=, =load_status()=.
- Input injection: =notify_input_event(InputEvent) -> InputEventId=,
  =notify_scroll_event=, =set_focused=, =resize=, =set_page_zoom=.
- Scripting: =evaluate_javascript= (returns serialized values via
  =JSValue= in embedder_traits).
- Screenshots: =take_screenshot(Option<WebViewRect>, callback)= —
  waits for load events + render-blocking elements before firing;
  =ScreenshotCaptureError= in embedder_traits.
- Accessibility: =set_accessibility_active= (accesskit tree updates via
  =WebViewDelegate::notify_accessibility_tree_update= — documented in
  the Servo Book print.html).
- User content: =user_content_manager()= (user scripts/styles).
- Delegates (embedder_traits / components/servo/webview_delegate.rs):
  dialogs incl. =AuthenticationRequest= (HTTP auth!), permission
  requests, file pickers, =CreateNewWebViewRequest= — these map cleanly
  onto Emacs minibuffer prompts.

* servo-capi: a C ABI for embedding (verified, young)

=ffi/capi= ("servo-capi"), README quote: "This crate provides a C FFI
wrapper for Servo's native Rust API. The goal is to allow Servo to be
consumed by embedders in other languages and eventually also provide a
stable ABI…". Tests in =tests/capi=.
https://github.com/servo/servo/tree/main/ffi/capi
Exported C functions (verified by reading the source):
- =servo_builder_set_preferences / set_options / set_event_loop_waker /
  build / free=
- =servo_webview_builder_create / set_url / set_delegate / build / free=

  set_hidpi_scale_factor / get_hidpi_scale_factor / free=

* Devtools / CDP status — the hard truth (verified)

- The =devtools= crate is an *actor-based remote devtools server
  implementing the Firefox devtools protocol* ("Only tested with
  nightly Firefox versions" — crate doc comment). NOT CDP.
  https://github.com/servo/servo/blob/main/components/devtools/lib.rs
- CDP implementation attempt: issue/PR #18133 "[WIP] Chrome DevTools
  Protocol implementation" — CLOSED, not merged.
  https://github.com/servo/servo/issues/18133
- WebDriver BiDi: open feature request #42766.
  https://github.com/servo/servo/issues/42766
- Servo Book contains zero CDP mentions (print.html grep).
- ⇒ eservo must NOT assume CDP. Driving surfaces available today:
  1) libservo in-process API (=notify_input_event=, JS eval, …),
  2) W3C WebDriver (servoshell =--webdriver=),
  3) devtools protocol (Firefox-flavored, low value for us).
  Whether servo's WebDriver supports cookie/storage commands
  (W3C "Get All Cookies" etc.) = VERIFY (questions.org).

* Verdict for eservo

An offscreen/embedding path EXISTS today and is exercised in-tree:
=SoftwareRenderingContext= + =WebViewBuilder= + =notify_input_event= +
=evaluate_javascript= + =take_screenshot= + =SiteDataManager= +
=Opts.config_dir=. The cheapest complete v0 is a Rust embedder (like
winit_minimal, minus the window) — which is exactly spike S0.1.
