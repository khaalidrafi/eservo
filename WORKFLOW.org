#+TITLE: eservo WORKFLOW — async review-later protocol
#+OPTIONS: toc:1

Mirrors team law: *humans review later, agents verify now.*

* Branches & commits

- All work lands on =ai/main= in *small* commits (one question, one
  spike, one doc per commit when practical).
- The initial scaffold (this repo state) is deliberately *uncommitted*:
  the first working agent commits it wholesale as
  =scaffold: eservo research-phase skeleton= and tags the REVIEW queue.
- No force-push, no history rewrite once reviewed.

* Evidence rule (per commit)

Every non-trivial commit message body carries:
- WHAT question it answers,
- EVIDENCE: artifact path (=evidence/…=, =RESEARCH/…=) or upstream URL,
- VERIFY list for anything still open.

Claims about Servo/Emacs APIs without a URL or artifact are review
blockers. Never invent servo APIs — check
RESEARCH/servo-embedding.org first; if absent, verify against upstream
before writing.

* Verification discipline (agents, now)

- Spikes must produce artifacts: PNGs, logs, timings, command
  transcripts. A spike that fails still commits its failure log.
- Research notes carry a *fetched-on date* + exact URLs.
- Unverified statements get the literal marker =VERIFY= (see
  RESEARCH/questions.org for the open list).

* Elisp quality bar (sandbox note)

- *No Emacs exists in this sandbox* → byte-compilation is NOT required
  for =elisp/eservo.el= until an environment provides it.
- Discipline instead: balanced parens, =checkdoc=-style docstrings,
  no suspected free variables; first Emacs-equipped agent runs
  =byte-compile-file= and fixes warnings before Phase 1 merges.
- =elisp/eservo.el= is a *design stub*: it must load-fail loudly
  (backend signals) rather than pretend to work.

* Rust quality bar

- =rust/= is a workspace skeleton; crates must always =cargo check=
  clean. The servo git dependency is intentionally absent until
  specs/0010 runs (see rust/Cargo.toml comment).
